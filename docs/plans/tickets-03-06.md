## Issue 6 — Domain schemas: Zod models (amended by v0 schema deltas)

**Goal:** the single source of truth for all data shapes. Schema-first; types via `z.infer` only. This encodes IMPLEMENTATION_PLAN §4 **as amended by `docs/architecture/v0-schema-deltas.md` §1–3** — the block below is the reconciled, authoritative shape; do not consult the two docs to re-derive it.
**Depends on:** Issue 3.

### Exact files

```
src/domain/schemas.ts
src/domain/types.ts        # z.infer exports ONLY — no interfaces, no manual types
src/domain/ids.ts          # export const newId = (): string => crypto.randomUUID();
src/domain/schemas.test.ts
```

### Authoritative schema (implement exactly; deviations require a flagged PR comment)

```ts
import { z } from "zod";

export const DateStringSchema = z.string().regex(/^\d{4}-\d{2}-\d{2}$/);        // local calendar date
export const TimeStringSchema = z.string().regex(/^([01]\d|2[0-3]):[0-5]\d$/);  // local HH:mm

export const RawLogSchema = z.object({
  id: z.string().uuid(),
  text: z.string().min(1),           // verbatim, immutable after save
  loggedAt: z.string().datetime(),   // machine-generated creation instant — real timestamp is correct here
  source: z.literal("manual"),       // widen later: "agent" | "import"
  schemaVersion: z.literal(1),
});

export const UncertaintyFlagSchema = z.object({
  field: z.string().min(1),          // e.g. "date", "payload.weightKg"
  reason: z.string().min(1),
});

export const WorkoutPayloadSchema = z.object({
  kind: z.literal("workout"),
  exercises: z.array(z.object({
    name: z.string().min(1),         // as logged — NO name normalization
    sets: z.array(z.object({
      reps: z.number().int().nonnegative().nullable(),
      weightKg: z.number().nonnegative().nullable(),
      rpe: z.number().min(1).max(10).nullable(),
    })),
  })),
  durationMin: z.number().positive().nullable(),
  notes: z.string().nullable(),
});

export const MealPayloadSchema = z.object({
  kind: z.literal("meal"),
  description: z.string().min(1),
  kcal: z.number().nonnegative().nullable(),      // user-STATED only — never computed
  proteinG: z.number().nonnegative().nullable(),  // user-STATED only — never computed
});

export const BodyweightPayloadSchema = z.object({
  kind: z.literal("bodyweight"),
  weightKg: z.number().positive(),
});

export const SleepPayloadSchema = z.object({
  kind: z.literal("sleep"),
  durationH: z.number().positive().nullable(),
  quality: z.enum(["poor", "ok", "good"]).nullable(),
});

export const NotePayloadSchema = z.object({
  kind: z.literal("note"),
  text: z.string().min(1),           // safety net — unparseable text is never dropped
});

export const PainPayloadSchema = z.object({    // per v0-schema-deltas §1
  kind: z.literal("pain"),
  bodyPart: z.string().nullable(),
  description: z.string().min(1),
  severity: z.number().int().min(1).max(10).nullable(), // only if user stated a number — NEVER inferred
  notes: z.string().nullable(),
  // NO diagnosis/treatment/cause/risk fields. Do not add without product review.
});

export const EventPayloadSchema = z.discriminatedUnion("kind", [
  WorkoutPayloadSchema, MealPayloadSchema, BodyweightPayloadSchema,
  SleepPayloadSchema, NotePayloadSchema, PainPayloadSchema,
]);

export const DraftEventSchema = z.object({     // date/time per deltas §3; parserVersion per deltas §2
  id: z.string().uuid(),
  rawLogId: z.string().uuid(),
  date: DateStringSchema,
  time: TimeStringSchema.nullable(),           // only if the user stated a time
  payload: EventPayloadSchema,
  uncertaintyFlags: z.array(UncertaintyFlagSchema),
  sourceText: z.string().min(1),               // raw segment this event came from
  parserVersion: z.string().min(1),            // e.g. "mock-v1"
  schemaVersion: z.literal(1),
});

export const CanonicalEventSchema = DraftEventSchema.extend({  // per deltas §2
  confirmedAt: z.string().datetime(),
  editedByUser: z.boolean(),
  provenance: z.literal("user_confirmed"),     // widen to a union later
  originalPayload: EventPayloadSchema,         // draft payload snapshot BEFORE user edits; never updated after confirm
});
```

`types.ts` exports `RawLog`, `UncertaintyFlag`, `EventPayload`, `WorkoutPayload` (etc.), `DraftEvent`, `CanonicalEvent` via `z.infer<typeof …>` — nothing else.

### Acceptance criteria

- [ ] Schemas match the block above field-for-field (names, nullability, constraints)
- [ ] All six payload kinds present, including `pain`; union rejects unknown `kind`
- [ ] `date` rejects datetimes (`"2026-07-11T10:00:00Z"`), non-padded dates (`"2026-7-1"`); `time` rejects `"24:00"`, `"9:5"`
- [ ] `CanonicalEventSchema` extends `DraftEventSchema` with exactly `confirmedAt`, `editedByUser`, `provenance`, `originalPayload`
- [ ] `severity: 0` and `severity: 11` fail; `severity: null` passes
- [ ] No `any`; no manual interfaces; no coercion (`z.coerce`) anywhere
- [ ] `newId()` returns a value accepted by `z.string().uuid()`

### Test strategy

Table-driven tests in `schemas.test.ts`:

1. One valid + ≥2 invalid samples per payload kind (wrong type, out-of-range, missing required).
2. One fully valid `DraftEvent` and `CanonicalEvent`; invalid variants for each added canonical field.
3. Date/time regex edge cases listed in acceptance criteria.
4. For one failure case, assert the Zod error `path` points at the offending field (proves errors are debuggable, feeds the Issue-8 quarantine design).
5. Round-trip: `Schema.parse(JSON.parse(JSON.stringify(validSample)))` succeeds (export-safety).

### Edge cases

- `reps: 0` is valid (failed set is real data); `weightKg: null` is valid (bodyweight exercises). Reviewer should consciously confirm these two decisions.
- `time: "00:00"` is valid (midnight, not "missing").
- Empty `exercises: []` on workout is valid at schema level — the parser decides whether that's a flag, not the schema.
- Extra unknown keys: Zod default (strip) is accepted for v0; do not switch to `.strict()` without flagging.

### Out of scope

Storage, migrations, parser logic, briefing schemas, plan schemas, provenance values beyond `"user_confirmed"`, any additional event kinds.
